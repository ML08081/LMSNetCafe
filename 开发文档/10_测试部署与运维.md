# 测试部署与运维

## 1. 测试策略

测试分为以下层级：

| 层级 | 目标 |
| --- | --- |
| 单元测试 | 验证计费、余额、状态流转等核心函数 |
| 接口测试 | 验证 API 参数、权限、响应和异常 |
| 集成测试 | 验证充值、开机、计费、结算完整流程 |
| 前端测试 | 验证页面加载、表单、按钮和状态提示 |
| 桌宠测试 | 验证连接、显示、提醒和断线重连 |
| 部署测试 | 验证环境变量、数据库、服务健康检查 |

## 2. 核心测试用例

### 2.1 会员充值

- 正常充值 100 元，余额增加 100 元。
- 充值带赠送金额，余额增加充值金额和赠送金额。
- 充值金额为 0 或负数时拒绝。
- 会员被冻结时是否允许充值，应根据业务配置验证。

### 2.2 开始上机

- 会员余额充足，设备空闲，开机成功。
- 会员余额不足，开机失败。
- 会员被冻结，开机失败。
- 设备使用中，开机失败。
- 同一会员已有进行中会话，开机失败。
- 人脸验证失败，开机失败或进入人工处理。

### 2.3 下机结算

- 正常下机，生成消费记录，扣减余额。
- 重复提交结算，只扣费一次。
- 会话不存在，返回错误。
- 会话已结束，返回明确错误。
- 余额不足时按业务规则处理。

### 2.4 自动计费

- 不足最小计费时长时按最小计费规则计算。
- 超过一个计费单位时正确累计费用。
- 低余额时触发提醒。
- 自动任务失败后下一轮可继续补算。

### 2.5 桌宠

- 客户机绑定设备编号后可连接后端。
- 开始上机后收到 `SESSION_STARTED`。
- 计费变化后收到 `SESSION_UPDATED`。
- 低余额后收到 `LOW_BALANCE`。
- 下机后收到 `SESSION_ENDED`。
- WebSocket 断开后自动重连。

## 3. 开发环境部署

推荐本地开发依赖：

- JDK 17+
- Maven 3.9+
- Node.js 20+
- Python 3.11+
- MySQL 8
- Redis 7

启动顺序：

```text
1. 启动 MySQL
2. 执行 scripts/init-db.sql
3. 启动 Redis
4. 启动 backend
5. 启动 face-service
6. 启动 frontend-admin
7. 启动 desktop-pet
```

## 4. 生产部署建议

### 4.1 服务部署

| 服务 | 部署方式 |
| --- | --- |
| 后端服务 | JAR 包或 Docker |
| 前端管理端 | Nginx 静态资源 |
| 人脸服务 | Python 虚拟环境或 Docker |
| MySQL | 独立数据库服务 |
| Redis | 独立缓存服务 |
| 桌宠 | Windows 安装包 |

### 4.2 端口建议

| 服务 | 端口 |
| --- | --- |
| 后端 | 8080 |
| 前端开发服务 | 5173 |
| 人脸服务 | 9000 |
| MySQL | 3306 |
| Redis | 6379 |

## 5. 配置管理

敏感配置不要写死在代码中：

- 数据库密码。
- JWT 密钥。
- 人脸特征加密密钥。
- 文件存储路径。
- 管理员初始密码。

建议通过环境变量或部署配置文件管理。

## 6. 日志规范

必须记录：

- 登录成功和失败。
- 用户、角色、权限变更。
- 会员充值。
- 上机开始、续费、下机结算、强制下机。
- 设备状态变更。
- 人脸验证结果。
- 自动计费任务异常。

日志中避免输出：

- 明文密码。
- 完整身份证号。
- 人脸特征向量。
- JWT 完整令牌。

## 7. 数据备份

建议：

- 每日自动备份 MySQL。
- 保留最近 7 天每日备份。
- 保留最近 3 个月每周备份。
- 重要版本发布前手动备份。
- 定期执行恢复演练。

## 8. 健康检查

后端：

```text
GET /api/v1/health
```

人脸服务：

```text
GET /face-service/health
```

健康检查内容：

- 服务是否启动。
- 数据库是否可连接。
- Redis 是否可连接。
- 人脸模型是否加载。

## 9. 发布检查清单

- 数据库脚本已备份并验证。
- 后端配置使用生产环境参数。
- 前端 API 地址正确。
- 人脸服务只允许内网访问。
- 初始管理员密码已修改。
- 关键接口权限已开启。
- 桌宠连接地址配置正确。
- 日志目录存在且有写入权限。
- 回滚方案已准备。
