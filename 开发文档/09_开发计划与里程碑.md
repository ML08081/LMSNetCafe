# 开发计划与里程碑

## 1. 阶段划分

| 阶段 | 目标 | 产出 |
| --- | --- | --- |
| 第 0 阶段 | 文档规划 | 开发文档、技术路线、任务拆分 |
| 第 1 阶段 | 基础工程搭建 | 后端、前端、数据库脚本、基础启动 |
| 第 2 阶段 | 基础业务 | 登录、会员、设备、充值 |
| 第 3 阶段 | 上机计费核心闭环 | 开机、自动计费、续费、下机结算 |
| 第 4 阶段 | 统计和报表 | 看板、营业统计、记录查询 |
| 第 5 阶段 | 人脸认证 | 录入、验证、日志 |
| 第 6 阶段 | 桌面桌宠 | 客户端展示、WebSocket、提醒 |
| 第 7 阶段 | 联调和部署 | 测试、打包、部署文档 |

## 2. 第 1 阶段任务

目标：项目可以启动，前后端能连通。

任务：

- 初始化 Spring Boot 后端工程。
- 初始化 Vue 3 管理端工程。
- 编写 MySQL 初始化脚本。
- 配置统一响应和全局异常处理。
- 配置登录接口骨架。
- 配置前端路由、布局和请求封装。
- 添加开发启动脚本。

验收：

- 后端健康检查接口可访问。
- 前端登录页可打开。
- 前端可请求后端健康检查。
- 数据库脚本可执行。

## 3. 第 2 阶段任务

目标：完成会员、设备、充值基础业务。

任务：

- 用户登录和 JWT 鉴权。
- 会员注册、查询、编辑、冻结。
- 会员账户创建。
- 会员充值和充值记录。
- 设备新增、查询、状态修改。
- 前台工作台会员搜索。

验收：

- 新会员注册后自动创建账户。
- 充值后余额和充值记录一致。
- 设备状态能在页面正确展示。

## 4. 第 3 阶段任务

目标：完成上机计费闭环。

任务：

- 计费规则管理。
- 开始上机。
- 当前会话查询。
- 自动计算当前消费。
- 低余额提醒。
- 下机结算。
- 强制下机。
- 防重复结算。

验收：

- 会员可选择空闲机位开始上机。
- 上机后设备状态变为使用中。
- 下机后费用正确扣除，设备恢复空闲。
- 重复点击结算不会重复扣费。

## 5. 第 4 阶段任务

目标：形成业务看板和统计查询。

任务：

- 今日营业额。
- 今日充值金额。
- 当前在线人数。
- 机位使用率。
- 上机记录查询。
- 充值记录查询。
- 消费记录查询。

验收：

- 看板数据能随着业务操作变化。
- 统计页面支持时间范围筛选。

## 6. 第 5 阶段任务

目标：接入人脸认证。

任务：

- 人脸服务基础 FastAPI 工程。
- 人脸录入接口。
- 人脸验证接口。
- 后端人脸档案管理。
- 前端摄像头采集。
- 验证日志查询。
- 开始上机前的人脸验证开关。

验收：

- 会员可完成人脸录入。
- 上机前可进行人脸验证。
- 验证结果写入日志。
- 人脸服务不可用时业务有明确提示。

## 7. 第 6 阶段任务

目标：完成桌宠客户端。

任务：

- Electron 工程初始化。
- 透明桌面窗口。
- 设备编号配置。
- WebSocket 连接。
- 显示上机时长、消费、余额。
- 低余额提醒。
- 休息提醒。
- Windows 打包。

验收：

- 桌宠可运行在 Windows 桌面。
- 开始上机后桌宠显示当前会话。
- 下机后桌宠回到待机状态。
- 断线后能自动重连。

## 8. 风险和处理

| 风险 | 处理 |
| --- | --- |
| 计费重复扣款 | 使用事务、状态条件更新和乐观锁 |
| 人脸识别不稳定 | 先用模拟服务打通流程，再替换真实模型 |
| 桌宠影响用户操作 | 控制窗口大小、透明度和置顶策略 |
| 客户机离线 | 后端为计费权威，客户端只展示状态 |
| 数据统计变慢 | 后期增加汇总表或缓存 |

## 9. 优先级

P0：

- 登录。
- 会员注册和充值。
- 设备状态。
- 开机和下机结算。

P1：

- 数据统计。
- 计费规则。
- 低余额提醒。
- 操作日志。

P2：

- 人脸认证真实模型。
- 桌宠动画增强。
- 权限细粒度配置。
- 报表导出。
