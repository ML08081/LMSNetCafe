# 智能服务助手与 AI 经营日报

日期：2026-10-27

## 1. 功能入口

| 使用人 | 入口 | 功能 |
| --- | --- | --- |
| 普通会员 | 左侧“智能服务助手”，或“我的首页”常用服务 | 查询本人余额、当前上机费、预计结算后余额和预算剩余时长，解释计费、上机、人脸、充值、报修和点餐流程 |
| 有统计权限的管理员 | 左侧“AI 经营日报”，或经营看板右上角按钮 | 按日期生成日报、保存统计快照、查看最近 30 个日期的日报、重新生成和导出文本 |

按当前选择先完成通用模型接入，暂不安装模型或填写密钥。未启用模型时，功能可以使用，页面明确显示“基础问答”或“基础统计摘要”；这部分是业务查询与内置规则，不冒充大模型。配置并成功调用模型后显示“AI 回答”或“AI 分析”。

## 2. 模型配置

配置只放在服务主机根目录 `.env`，不要放到前端或提交 Git。主服务使用 Chat Completions 兼容接口，可连接符合该协议的本地部署或在线服务。参考 [OpenAI 官方接口说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

```dotenv
# 在已经部署/开通模型服务后启用；名称由实际服务提供
AI_ENABLED=true
AI_BASE_URL=http://127.0.0.1:11434/v1
AI_MODEL=你的实际模型名称
# 无密钥的本地服务可留空；在线服务在本机填写真实密钥
AI_API_KEY=
AI_TIMEOUT_SECONDS=12
AI_MAX_OUTPUT_TOKENS=1600
AI_TOKEN_PARAMETER=max_completion_tokens
```

`AI_BASE_URL` 填接口基础地址，不带 `/chat/completions`，后端会追加路径。在线服务替换为其 HTTPS 基础地址；`11434` 示例仅适用于已经在该端口部署兼容接口的本地服务。程序不会自动安装或启动模型。

输出上限字段默认 `max_completion_tokens`，如果选择的兼容服务要求 `max_tokens`，设置 `AI_TOKEN_PARAMETER=max_tokens`。请求不固定温度参数，具体模型兼容性仍需用实际服务验证。超时限制为 1–15 秒，输出上限为 128–4096 token；较慢的本地模型需预热并选择能够在该时间内返回的模型/输出长度。模型返回空结果、不完整结果、配置错误、鉴权失败或超时均回退为基础结果，提示真实原因类别，不显示供应商响应和密钥。

修改后重启后端。状态页面的“模型已配置”表示配置项完整，不代表网络已验证；发送问题或生成日报后，应出现“AI 回答/AI 分析”标签，才表明本次模型调用成功。

所有模型调用在后端进行，不自动执行 SQL，不赋予模型充值、退款、开机或结算能力。会员请求与日报生成合计按每账号每分钟最多 10 次限制，单实例最多 3 个并行模型调用；日报生成单实例串行。用于当前单门店单主服务部署。

## 3. 智能助手如何保证回答有依据

1. 服务端从登录身份获取会员，不接受请求体传入的其他会员编号。
2. 实时读取本人余额和当前会话，复用上机计费服务；规则解释来自本地可维护的知识条目。
3. 按本次问题和近期对话检索知识，本次问题优先；每次提问重新查询，界面标明快照时间。
4. 模型只接收白名单字段：余额、账户状态、当前机位与区域、计费单价、时长、当前费用、预算估算、启用计费规则及相关知识。不会查询其他会员资料，亦不会加入姓名、手机号、身份证、人脸图片/特征、系统密钥或门店经营总账。
5. 回答旁显示业务数据卡片和来源链接。预算剩余时长为保守估算，后续商品消费会减少预算，实际费用以下机结算为准。
6. 问答文本按普通文本展示，不执行模型输出的 HTML 或脚本。对话只保留在当前页面内存，可清空；刷新、退出后不保存聊天记录。

启用在线服务后，问题文本、上述最小业务上下文及最近最多 8 条对话会发送到所配置服务。使用者应避免在提问中主动填写身份证或人脸资料。

## 4. 经营日报统计口径

| 指标 | 口径 |
| --- | --- |
| 消费正向金额、退款、净消费 | 从 `consume_record` 按入账日期统计，净消费为正向金额减负向退款；包含当日入账的历史订单退款 |
| 上机 / 商品服务消费 | 按 `MACHINE` / `SHOP` 流水分类展示；独立 `REFUND` 流水不能还原原品类，不强行分摊 |
| 充值实收与赠送 | 从 `recharge_record` 分别统计；不与净消费重复相加，不据此计算利润 |
| 新开会话与结算次数 | 分别按 `start_at` 与已结束会话的 `end_at` 归属日期，二者可能不同 |
| 到店会员 | 所选日期内有实际重叠会话的会员去重，跨天会话也计入 |
| 区域机时 | 将跨天会话裁剪到所选日，进行中会话最多统计到生成时，统一由数据库时间计算 |
| 利用率 | 区域机时 ÷ 当前未删除机位数对应的该日期已流逝机时；历史设备增减未保存，明确标注为估算 |
| 故障 / 待处理订单 | 当日新增故障按上报时间统计；当前故障机位、空闲机位、未解决工单及待处理订单另外标为生成时实时状态 |
| 前日变化 | 对比前一天净消费；前日为零或负数时不输出增长百分比 |

默认日期以中国标准时间确定，账目按数据库保存的业务日期统计；数据库应按门店业务时区运行。可选择最近五年内且不晚于今天的日期。无数据时显示零与数据不足说明，不编造趋势或经营原因。

日报保存到新表 `ai_daily_report`，每日期一条。读取已保存日报不会调用模型或重新统计，也不会产生模型调用费用；“重新生成”会在确认后覆盖该日期快照与分析。数据新增、补录和退款发生后，可重新生成今日或对应日期的日报。

日报仅上传汇总指标和区域统计，不上传会员明细。模型生成的是解释和建议，页面的指标卡、表格和统计口径来自业务查询，不采用模型计算结果。

## 5. 升级与同步

```powershell
# 另一台电脑在项目目录更新；新版已包含同步脚本
npm run sync
# 停止本项目旧服务后启动新版
powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1 -Stop
npm run start:lan
```

后端启动时只增量创建 `ai_daily_report`，需要当前数据库账号有建表权限。不要重新执行 `scripts/init-db.sql`，不需要重置原有会员、余额和会话。两台电脑使用同一后端时，只需在后端主机配置模型；前端通过原有代理访问。

Git 同步代码和 `.env.example`，不传输 `.env` 密钥或已生成的数据库日报。使用独立数据库的两台电脑各自保存日报；需要相同结果时共用主机后端和数据库。

## 6. 演示验收

1. 暂不配置模型：会员打开助手询问“我现在下机需要多少钱”，核对余额和费用卡片与工作台一致，回答标为“基础问答”。
2. 追问“为什么刚上机就产生费用”“怎样报修当前机位”，检查规则说明和跳转；请求充值时应提供办理指引，不修改账户。
3. 换另一位会员登录，查询依据必须随身份改变。会员不能访问 AI 经营日报接口。
4. 管理员选择有实际交易的日期生成日报，核对消费、退款、充值分列，以及跨天会话机时；零数据日期不应编造经营情况。
5. 查看最近日期、重新生成并导出，核对导出包含生成模式、统计口径和完整快照。
6. 后续配置模型，再提问和生成一次日报，检查成功标签为“AI 回答 / AI 分析”。临时关闭模型服务后应明确回退，原有上机和结算功能继续工作。

自动化验证包含：账户归属和只读行为、角色权限、请求校验、限流、模型 HTTP 协议、鉴权与异常响应、未配置模型回退、账本净额、充值分离、零基期、跨天机时、日报持久化与重新生成。前端还需检查实际浏览器的提问、清空、来源卡片、日报和下载流程。用户尚未配置实际模型，因此实际供应商的模型质量、可用性和费用待配置后验收。
