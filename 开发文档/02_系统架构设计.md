# 系统架构设计

## 1. 总体架构

系统采用前后端分离和模块化服务设计：

```text
管理端 Web / 前台工作台
        |
        | REST API / WebSocket
        v
Spring Boot 后端服务
        |              |
        | HTTP         | MySQL / Redis
        v              v
Python 人脸认证服务   数据存储与状态缓存
        ^
        |
客户机 Electron 桌宠
```

## 2. 服务划分

### 2.1 后端主服务

职责：

- 用户登录、JWT 认证、权限校验。
- 会员、充值、消费、设备、上机会话管理。
- 自动计费和结算。
- 数据统计和报表接口。
- 对接人脸认证服务。
- 通过 WebSocket 向桌宠推送上机状态。

### 2.2 前端管理端

职责：

- 管理后台页面。
- 前台收银工作台。
- 设备机位视图。
- 会员充值和消费记录。
- 数据统计看板。

### 2.3 人脸认证服务

职责：

- 接收人脸图片。
- 检测人脸质量。
- 提取特征向量。
- 与会员特征库比对。
- 返回相似度和识别结果。

人脸服务不直接修改业务数据，所有业务决策由后端主服务完成。

### 2.4 桌面桌宠客户端

职责：

- 绑定客户机设备编号。
- 接收后端推送的上机会话状态。
- 展示已用时长、当前费用、余额提醒和休息提醒。
- 可向后端上报在线状态。

## 3. 核心模块边界

| 模块 | 核心实体 | 边界 |
| --- | --- | --- |
| 系统管理 | User、Role、Permission | 只负责账号和权限，不处理会员余额 |
| 会员管理 | Member、MemberAccount、RechargeRecord | 负责会员资料和余额流水 |
| 上机计费 | MachineSession、BillingRule、ConsumeRecord | 负责会话、计费和结算 |
| 设备管理 | Device、DeviceFault、RepairRecord | 负责设备生命周期和状态 |
| 人脸认证 | FaceProfile、FaceVerifyLog | 负责特征和验证记录 |
| 数据统计 | 统计 DTO、报表查询 | 从业务表聚合，不直接写业务状态 |
| 桌宠通信 | ClientStatus、WebSocket Message | 负责推送和客户端心跳 |

## 4. 关键业务流程

### 4.1 开始上机流程

1. 前台选择会员。
2. 系统检查会员状态和余额。
3. 前台选择空闲机位。
4. 如果启用人脸验证，则调用人脸认证服务。
5. 后端创建上机会话。
6. 后端将设备状态改为使用中。
7. 后端通过 WebSocket 通知对应客户机桌宠。

### 4.2 自动计费流程

1. 定时任务扫描进行中的上机会话。
2. 根据开始时间、当前时间和计费规则计算应扣金额。
3. 如果达到扣费周期，则写入消费流水并更新会员余额。
4. 如果余额低于阈值，推送提醒。
5. 如果余额不足且规则要求强制下机，则进入自动结算。

### 4.3 下机结算流程

1. 前台或系统触发下机。
2. 后端锁定当前会话，防止重复结算。
3. 计算最终费用。
4. 写入消费记录和余额流水。
5. 更新会话状态为已结束。
6. 更新设备状态为空闲。
7. 通知桌宠清空会话状态。

### 4.4 人脸验证流程

1. 前端或客户机采集图片。
2. 后端接收图片并校验会员状态。
3. 后端调用人脸服务进行特征比对。
4. 后端根据相似度阈值判断是否通过。
5. 写入验证日志。
6. 返回验证结果给调用端。

## 5. WebSocket 通道设计

建议通道：

| 通道 | 发送方 | 接收方 | 用途 |
| --- | --- | --- | --- |
| `/ws/admin` | 后端 | 管理端 | 在线人数、设备状态、计费提醒 |
| `/ws/client/{deviceCode}` | 后端 | 桌宠 | 当前会话、余额、休息提醒 |
| `/ws/client-heartbeat` | 桌宠 | 后端 | 客户机在线状态 |

消息基本格式：

```json
{
  "type": "SESSION_UPDATED",
  "timestamp": "2026-08-31T08:00:00+08:00",
  "data": {}
}
```

## 6. 异常和一致性设计

- 充值和结算使用数据库事务。
- 上机会话结算需要使用乐观锁或状态条件更新，避免重复结算。
- 设备状态变更必须记录操作来源。
- 人脸服务不可用时，允许前台人工验证，但必须记录日志。
- 客户机离线时，不立即结束上机会话，由后端计费状态为准。
- 自动计费任务失败时记录错误，并允许下一轮继续补算。
