# 需求规划

## 1. 用户角色

| 角色 | 权限范围 |
| --- | --- |
| 超级管理员 | 系统配置、用户管理、角色权限、所有业务数据 |
| 店长/主管 | 会员管理、设备管理、营业统计、上机记录 |
| 前台收银 | 会员注册、充值、开机、续费、下机结算 |
| 维修人员 | 查看设备状态、登记故障、填写维修记录 |
| 会员 | 被管理对象，可通过人脸验证上机 |
| 客户机桌宠 | 客户端展示角色，仅接收当前上机状态和提醒 |

## 2. 功能范围

### 2.1 系统管理

- 登录、退出登录、刷新令牌。
- 用户管理：新增、编辑、停用、重置密码。
- 角色管理：管理员、店长、前台、维修人员。
- 权限管理：菜单权限和接口权限。
- 操作日志：记录关键管理操作。

### 2.2 会员管理

- 会员注册：姓名、手机号、身份证号、会员等级、初始余额。
- 会员信息：查询、编辑、冻结、解冻。
- 会员充值：创建充值流水，更新账户余额。
- 消费记录：查看上机消费、商品消费、扣费记录。
- 会员余额预警：低于阈值时提醒前台和桌宠。

### 2.3 人脸认证

- 人脸录入：采集会员人脸图片，生成人脸特征。
- 人脸识别：上传实时图片，与已录入特征进行比对。
- 上机身份验证：开机前或客户机登录时进行验证。
- 异常处理：未录入、识别失败、相似度过低、会员被冻结。

### 2.4 上机计费

- 选择机位：按区域、状态筛选可用设备。
- 开始上机：绑定会员、机位、计费规则，生成上机会话。
- 自动计费：按分钟或小时累计费用。
- 续费：会员充值或调整可用余额后延长使用时间。
- 下机结算：结束会话、生成消费记录、释放机位。
- 异常结算：断电、客户端离线、管理员强制下机。

### 2.5 设备管理

- 设备信息：编号、区域、配置、IP、状态。
- 设备状态：空闲、使用中、维护中、故障、停用。
- 故障登记：登记故障类型、描述、发现时间。
- 维修记录：处理人、维修结果、完成时间。

### 2.6 数据统计

- 营业统计：日营业额、充值金额、消费金额、活跃会员数。
- 上机记录：按会员、机位、时间范围查询。
- 充值记录：按收银员、支付方式、时间范围查询。
- 消费记录：按消费类型和会员查询。
- 可视化看板：今日收入、在线人数、机位使用率。

### 2.7 桌面桌宠

- 桌宠动画：常驻桌面，可拖拽，可隐藏。
- 上机时间显示：显示已上机时长和剩余可用时长。
- 当前消费显示：展示本次上机累计费用。
- 余额提醒：低余额、即将扣费失败时提醒。
- 休息提醒：连续上机达到阈值后提醒休息。

## 3. MVP 范围

第一阶段必须完成：

1. 管理员登录。
2. 会员注册、查询、充值。
3. 设备新增、状态管理。
4. 选择机位、开始上机、自动计费、下机结算。
5. 基础营业统计。
6. 桌宠显示上机时长、当前消费和余额提醒。

第二阶段接入：

1. 人脸录入和上机验证。
2. 更细的权限管理。
3. 维修流程。
4. 数据看板增强。
5. 客户机离线和异常结算处理。

## 4. 关键业务规则

- 会员被冻结时不能上机。
- 设备处于空闲状态时才能被选择上机。
- 同一会员同一时间只能存在一个进行中的上机会话。
- 开始上机后设备状态变为使用中。
- 下机结算后设备状态变为空闲，除非存在故障或维护标记。
- 计费金额按照计费规则和实际使用时长计算。
- 余额不足时系统应提醒，达到欠费限制时可强制下机或禁止继续上机。
- 人脸验证失败不应直接扣费，应提示前台人工处理。

## 5. 非功能需求

- 数据一致性：充值、消费和余额变更必须保留流水。
- 安全性：密码加密存储，人脸特征加密或脱敏存储。
- 可维护性：业务模块清晰拆分，核心计费逻辑单独封装。
- 可扩展性：人脸认证服务独立部署，后续可替换算法。
- 可观测性：关键操作、计费任务、支付流水需要日志记录。
- 可恢复性：数据库定期备份，异常结算可追踪。
