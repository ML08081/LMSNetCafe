# 局域网打包部署与数据互通技术文档

编写日期：2026-09-02

## 1. 文档目标

本文档用于指导将 LMSNetCafe 项目整体打包到另一台电脑，并在数据库保留在主机电脑的前提下，实现同一局域网内多电脑访问、业务数据实时互通和桌面宠物客户端联动。

本方案的核心原则是：业务数据只保存在主机电脑的 MySQL 中，访问端电脑不保存独立业务数据。所有充值、上机、结算、点餐、退款、服务呼叫、设备状态和桌宠设置，都必须通过后端接口写入主机数据库。

## 2. 推荐部署架构

推荐使用“主机统一服务，访问端远程访问”的方式。

```text
主机电脑
  ├── MySQL 数据库
  ├── Spring Boot 后端服务 8080
  ├── FastAPI 人脸服务 9000
  ├── Vue 网页服务 5173
  └── GitHub 仓库和项目源码

访问端电脑
  ├── 浏览器访问 http://主机IP:5173/login
  └── 桌面宠物连接 http://主机IP:8080
```

这种方式最稳，因为只有一套后端直接操作数据库，不会出现多台电脑各自运行数据库导致数据不一致的问题。

## 3. 数据实时互通设计

### 3.1 数据写入路径

| 操作 | 发起端 | 接口服务 | 最终写入位置 |
| --- | --- | --- | --- |
| 用户登录 | 任意电脑浏览器 | 主机后端 | `sys_user`、角色权限相关表 |
| 会员充值 | 前台页面 | 主机后端 | `member_account`、`recharge_record`、`member_account_flow` |
| 开始上机 | 前台页面 | 主机后端 | `machine_session`、`device_info` |
| 下机结算 | 前台页面 | 主机后端 | `machine_session`、`member_account`、`consume_record`、`member_account_flow`、`device_info` |
| 普通用户点餐 | 普通用户页面 | 主机后端 | `shop_order`、`shop_order_item`、`shop_product`、`member_account`、`consume_record`、`member_account_flow` |
| 订单取消退款 | 前台页面 | 主机后端 | `shop_order`、`shop_product`、`member_account`、`consume_record`、`member_account_flow` |
| 呼叫前台 | 普通用户页面 | 主机后端 | `service_call` |
| 故障反馈 | 普通用户页面 | 主机后端 | `device_fault` |
| 维修处理 | 管理员页面 | 主机后端 | `device_fault`、`repair_record`、`device_info` |
| 桌宠设置 | 普通用户页面 | 主机后端 | `member_pet_setting` |
| 桌宠状态同步 | 桌宠客户端 | 主机后端 | 读取 `machine_session`、`member_account`、`member_pet_setting` |

### 3.2 数据一致性保证

- 访问端不直接操作 MySQL，统一调用主机后端接口。
- 后端使用数据库事务处理结算、点餐、退款等多表更新。
- 点餐时后端重新读取商品价格并锁定库存，避免前端篡改金额。
- 会员账户余额变化必须同时写入账户流水。
- 桌宠不修改业务数据，只注册设备、上报心跳、读取当前会话快照。

## 4. 本次为局域网部署完成的项目调整

### 4.1 后端跨域配置

后端已支持通过环境变量配置允许访问来源：

```text
CORS_ALLOWED_ORIGIN_PATTERNS=http://localhost:*,http://127.0.0.1:*,http://192.168.*:*,http://172.*:*,http://10.*:*
```

这样另一台电脑使用本地前端访问主机后端时，不会因为浏览器跨域策略导致接口失败。

### 4.2 前端代理配置

前端 Vite 代理已支持环境变量：

```text
VITE_PROXY_API_TARGET=http://主机IP:8080
VITE_API_BASE_URL=http://主机IP:8080/api/v1
```

访问端电脑如果运行自己的前端开发服务，可以把接口指向主机后端。

### 4.3 桌宠连接配置

桌宠已支持三种方式配置主机后端地址：

1. 桌宠设置面板中填写服务地址。
2. 使用环境变量：

```powershell
$env:LMS_PET_SERVER_URL = "http://主机IP:8080"
$env:LMS_PET_DEVICE_CODE = "PC-A02"
```

3. 使用启动参数：

```powershell
.\LMS网咖桌宠.exe --server-url=http://主机IP:8080 --device-code=PC-A02
```

桌宠保存配置后会写入当前 Windows 用户数据目录，后续启动会继续使用该配置。

### 4.4 打包脚本

新增局域网交付打包脚本：

```powershell
npm run package:lan
```

输出位置：

```text
F:\LMSNetCafe\packages\LMSNetCafe-lan-package.zip
```

该压缩包会排除 `node_modules`、`target`、`dist`、`.venv`、日志和临时构建目录，适合拷贝到另一台电脑后重新安装依赖。

## 5. 主机电脑配置步骤

以下步骤在保留数据库的主机电脑上执行。

### 5.1 确认主机局域网 IP

在 PowerShell 执行：

```powershell
ipconfig
```

找到当前正在使用的 WLAN 或以太网 IPv4 地址，例如：

```text
172.16.60.121
```

后文统一用 `主机IP` 表示该地址。

### 5.2 启动数据库

如果 MySQL 在 WSL Ubuntu 中，先进入 WSL：

```powershell
wsl
```

在 Ubuntu 中检查 MySQL：

```bash
sudo service mysql status
sudo service mysql start
```

数据库名：

```text
lms_netcafe
```

本机后端连接数据库时仍然可以使用：

```text
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=123456
```

### 5.3 初始化数据库

在主机项目目录执行：

```powershell
mysql -h 127.0.0.1 -P 3306 -u root -p123456 < scripts\init-db.sql
```

如果 Windows 没有 `mysql` 命令，可以在 WSL 中进入项目挂载目录后执行：

```bash
mysql -h 127.0.0.1 -P 3306 -u root -p123456 < /mnt/f/LMSNetCafe/scripts/init-db.sql
```

### 5.4 启动人脸服务

在人脸服务目录安装依赖后启动：

```powershell
cd F:\LMSNetCafe
.\scripts\dev-start.ps1 -Face -FaceBindHost 127.0.0.1
```

说明：如果只有主机后端调用人脸服务，人脸服务保持 `127.0.0.1` 即可，不需要暴露给其他电脑。

### 5.5 启动后端服务

使用主机数据库和本机人脸服务：

```powershell
cd F:\LMSNetCafe
$env:DB_HOST = "127.0.0.1"
$env:DB_PORT = "3306"
$env:DB_NAME = "lms_netcafe"
$env:DB_USER = "root"
$env:DB_PASSWORD = "123456"
$env:FACE_SERVICE_URL = "http://127.0.0.1:9000"
$env:CORS_ALLOWED_ORIGIN_PATTERNS = "http://localhost:*,http://127.0.0.1:*,http://192.168.*:*,http://172.*:*,http://10.*:*"
.\scripts\dev-start.ps1 -Backend -BindHost 0.0.0.0
```

后端健康检查：

```text
http://主机IP:8080/api/v1/health
```

### 5.6 启动网页端

主机网页端推荐使用 Vite 代理访问本机后端：

```powershell
cd F:\LMSNetCafe
.\scripts\dev-start.ps1 -Admin -BackendBaseUrl http://127.0.0.1:8080
```

同一局域网访问入口：

```text
http://主机IP:5173/login
```

### 5.7 放行 Windows 防火墙

用管理员 PowerShell 执行：

```powershell
New-NetFirewallRule -DisplayName "LMSNetCafe Frontend 5173" -Direction Inbound -Protocol TCP -LocalPort 5173 -Action Allow
New-NetFirewallRule -DisplayName "LMSNetCafe Backend 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

人脸服务默认不需要对访问端开放。如果确实要让其他电脑直接调用人脸服务，再放行 `9000`。

## 6. 访问端电脑使用方式

### 6.1 方式一：只用浏览器访问

这是最推荐的访问端方式。另一台电脑不需要安装 Java、Node、Python 和数据库，只需要浏览器访问：

```text
http://主机IP:5173/login
```

测试账号：

| 账号 | 密码 | 角色 |
| --- | --- | --- |
| `admin` | `123456` | 超级管理员 |
| `cashier` | `123456` | 前台人员 |
| `member001` | `123456` | 普通用户 |

### 6.2 方式二：访问端本地运行前端

如果希望把项目复制到另一台电脑，并在访问端本地启动前端页面，执行以下步骤。

1. 在主机打包：

```powershell
cd F:\LMSNetCafe
npm run package:lan
```

2. 把压缩包复制到访问端电脑并解压。

3. 在访问端创建 `.env`，内容可参考：

```text
deploy\lan-client.env.example
```

需要把其中的 `172.16.60.121` 改成真实主机 IP。

4. 安装依赖并启动前端：

```powershell
npm install
npm --prefix frontend-admin install
.\scripts\dev-start.ps1 -Admin -EnvFile .env -BackendBaseUrl http://主机IP:8080
```

访问端本机打开：

```text
http://127.0.0.1:5173/login
```

此时页面运行在访问端电脑，但接口请求会写入主机后端和主机数据库。

## 7. 桌面宠物访问端部署

### 7.1 前置条件

每一台运行桌宠的电脑都必须在系统管理端存在对应设备编号，例如：

```text
PC-A01
PC-A02
PC-B01
```

设备编号必须与桌宠配置中的 `deviceCode` 一致。

### 7.2 开发版启动

在访问端项目目录执行：

```powershell
cd 解压后的项目目录
npm --prefix desktop-pet install
.\scripts\dev-start.ps1 -Pet -PetServerUrl http://主机IP:8080 -PetDeviceCode PC-A02
```

### 7.3 安装包方式

在主机或开发机生成安装包：

```powershell
npm --prefix desktop-pet run dist
```

安装后可以在桌宠设置面板中填写：

```text
服务地址：http://主机IP:8080
设备编号：PC-A02
```

也可以通过启动参数：

```powershell
.\LMS网咖桌宠.exe --server-url=http://主机IP:8080 --device-code=PC-A02
```

### 7.4 桌宠数据同步说明

桌宠连接主机后端后，会执行：

```text
注册设备 -> 获取 client_token -> 定时心跳 -> 拉取当前上机会话 -> 显示余额/消费/时长/提醒
```

普通用户在网页端关闭桌宠显示后，设置会保存到 `member_pet_setting`。桌宠下一次同步会读取该设置并自动隐藏。

## 8. 可选方案：访问端也运行后端，但共用主机数据库

一般不推荐访问端运行后端。只有在测试多后端实例时才使用该方式。

访问端后端需要连接主机数据库：

```powershell
$env:DB_HOST = "主机IP"
$env:DB_PORT = "3306"
$env:DB_NAME = "lms_netcafe"
$env:DB_USER = "lms_app"
$env:DB_PASSWORD = "强密码"
.\scripts\dev-start.ps1 -Backend -BindHost 0.0.0.0
```

如果 MySQL 在 WSL Ubuntu 中，需要额外配置 MySQL 监听局域网，并创建允许远程访问的账号。该方式会增加数据库暴露风险，正式使用更建议只暴露后端 `8080`，不暴露 MySQL `3306`。

## 9. 验证步骤

### 9.1 网络连通性

在访问端电脑执行：

```powershell
ping 主机IP
```

再测试后端：

```powershell
Invoke-WebRequest -UseBasicParsing http://主机IP:8080/api/v1/health
```

### 9.2 页面访问

访问：

```text
http://主机IP:5173/login
```

分别用 `admin`、`cashier`、`member001` 登录，确认三个角色页面不同。

### 9.3 数据实时互通验证

1. 在访问端用 `cashier` 登录，给 `M0001` 充值。
2. 在另一台电脑或主机用 `member001` 登录，查看余额是否变化。
3. 在普通用户页面下单购买饮品。
4. 在前台页面查看订单是否出现。
5. 前台取消订单，普通用户账户余额应恢复。
6. 启动桌宠并绑定同一设备，前台开始上机后桌宠应显示会员、时长、费用和余额。

### 9.4 数据库验证

在主机数据库中执行：

```sql
SELECT * FROM member_account WHERE member_id = 1;
SELECT * FROM member_account_flow WHERE member_id = 1 ORDER BY created_at DESC LIMIT 10;
SELECT * FROM shop_order ORDER BY created_at DESC LIMIT 10;
SELECT * FROM service_call ORDER BY created_at DESC LIMIT 10;
SELECT * FROM client_device ORDER BY updated_at DESC LIMIT 10;
```

如果这些表能看到访问端操作产生的新记录，说明数据已经实时写入主机数据库。

## 10. 常见问题处理

### 10.1 访问端打不开页面

检查：

- 访问端和主机是否在同一网络。
- 主机 IP 是否写错。
- 前端服务是否正在运行。
- Windows 防火墙是否放行 `5173`。

### 10.2 页面能打开但登录失败

检查：

- 后端服务是否正在运行。
- 访问端是否能打开 `http://主机IP:8080/api/v1/health`。
- 前端 `.env` 中 `VITE_API_BASE_URL` 或 `VITE_PROXY_API_TARGET` 是否指向主机 IP。
- 后端 CORS 是否包含访问端来源。

### 10.3 后端启动失败

检查：

- `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD` 是否正确。
- WSL Ubuntu 中 MySQL 是否启动。
- `lms_netcafe` 数据库是否已经初始化。
- `FACE_SERVICE_URL` 是否能访问。

### 10.4 桌宠连接失败

检查：

- 桌宠服务地址是否为 `http://主机IP:8080`。
- 设备编号是否已经在管理端创建设备。
- 后端 `8080` 是否放行。
- 桌宠本地配置是否仍保存旧的 `127.0.0.1`。

### 10.5 桌宠不显示或自动隐藏

检查：

- 普通用户网页端“桌面宠物”设置是否关闭。
- 桌宠是否在托盘中，可从托盘菜单点击“显示桌宠”。
- 当前绑定设备是否存在运行中的上机会话。
- 如果用户关闭了桌宠显示，需要到普通用户网页端重新开启。

### 10.6 数据没有同步

检查：

- 是否存在多套数据库。
- 访问端是否误连到了自己的本地后端。
- 后端环境变量 `DB_HOST` 是否指向主机数据库。
- 所有电脑是否都在访问同一个 `主机IP:8080` 后端。

## 12. 推荐最终使用方式

实际门店或答辩演示时，推荐保持以下形态：

```text
主机运行：数据库、后端、人脸服务、前端
访问端运行：浏览器、桌宠
GitHub 用途：同步代码和文档
MySQL 用途：保存实时业务数据
```

这种结构下，另一台电脑不需要保存数据库，也不需要直接连接数据库。只要访问主机 IP，所有业务操作都会进入同一套后端和同一套 MySQL，从而保证系统数据实时互通。
