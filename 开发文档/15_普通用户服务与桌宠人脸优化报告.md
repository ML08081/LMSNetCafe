# 普通用户服务、桌宠与人脸录入优化报告

## 1. 本次目标

本次针对普通用户端缺少门店服务能力、桌宠显示不完整且无法远程关闭，以及管理员/前台人脸录入要求过高三个问题进行了完整修复。所有新增业务均已连接 MySQL 和现有三角色权限体系，不使用前端模拟数据。

## 2. 普通用户服务中心

新增“呼叫与点餐”页面，权限为 `portal:services`，仅普通用户可见。主要能力如下：

- 呼叫前台、请求清洁、补充用品和设备协助，自动关联当前上机设备。
- 同类型未完成呼叫禁止重复提交，前台处理进度可在用户端查询。
- 展示饮品、零食和简餐的真实价格、库存与可售状态。
- 支持购物车数量调整、订单备注和预存余额支付。
- 后端在事务内锁定会员账户与商品库存，服务端重新计算金额，避免篡改价格和超卖。
- 支付后同步更新会员余额、累计消费、消费记录和账户流水。
- 订单取消时自动退款并恢复库存，同时记录退款消费与资金流水。

## 3. 前台与管理员服务工作台

新增“服务与订单”页面，权限为 `service:manage`。超级管理员和前台人员均可进入，普通用户不可访问。

- 服务呼叫状态：待响应、处理中、已完成、已取消。
- 点餐订单状态：待接单、准备中、配送中、已完成、已取消。
- 后端校验合法状态流转，已完成或已取消记录不可重新打开。
- 页面显示会员、机位、商品明细、实付金额、备注和发起时间。

## 4. 桌宠修复与网页设置

- 根据用户提供的吾皇猫参考图重新生成纯色背景素材，再通过色键算法生成透明 PNG。
- 修复旧素材把白色脸部、腹部和四肢错误识别为透明区域的问题。
- 新素材 `desktop-pet/public/wuhuang-cat-v2.png` 已用于 Vue 页面、Electron 托盘和安装包资源。
- 普通用户首页新增“桌面宠物”设置，可控制显示/隐藏、窗口置顶和提示气泡。
- 设置持久化到 `member_pet_setting`，客户机每 5 秒随会话快照同步。
- Electron 新增显示和置顶 IPC，隐藏后仍保持后台轮询，重新开启时无需重启程序。

## 5. 人脸录入优化

- 最低质量阈值由 55 调整为 35，适配普通门店摄像头和室内光照。
- 最小人脸尺寸由画面短边的约 1/6 放宽至约 1/9，固定下限由 72 像素降至 52 像素。
- 首次检测失败时增加更宽松的二次检测，最低可接受 44 像素人脸区域。
- 清晰度和人脸面积评分适度放宽，降低轻微抖动、距离偏远导致的误拒绝。
- 仍保留单人正脸、有效图片、5MB 大小限制和识别相似度阈值，未降低登录比对阈值。

## 6. 数据库与权限

新增数据表：

- `member_pet_setting`：会员桌宠偏好。
- `service_call`：门店服务呼叫。
- `shop_product`：商品与库存。
- `shop_order`、`shop_order_item`：订单主表与明细。

新增权限：

- `portal:services`：普通用户呼叫与点餐。
- `service:manage`：超级管理员和前台人员处理服务与订单。

初始化脚本已加入 8 个演示商品，并可重复执行。

## 7. 验证结果

- Java 后端 `mvn -DskipTests compile` 通过。
- 管理端 `npm run build` 通过，共转换 1705 个模块。
- 桌宠 Vue、Electron 主进程和 preload 构建通过。
- 人脸服务 Python 模块编译通过，运行时最低质量阈值为 35。
- 后端、人脸服务、管理端和桌宠开发服务健康检查均正常。
- 客户机 `PC-A01` 会话响应已返回 `petEnabled`、`petAlwaysOnTop` 和 `petShowBubble`。
- 真实支付回归：会员张三购买冰镇可乐，余额由 57.30 元降至 52.30 元，订单和前台处理均完成，商品库存同步扣减。
- 退款回归：测试订单支付后余额由 52.30 元降至 47.30 元，取消后恢复至 52.30 元，库存恢复至扣款前数量。
- 非人脸图片仍返回 422 和“未检测到正面人脸”，证明放宽录入条件后基本校验仍然有效。
